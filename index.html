A Point of View · 一个观点
服务即 Skill，
不必再造一个 App。 SERVICE AS A SKILL — NO APP REQUIRED

当智能体工作台成为大家的日常，一个封装好的 Skill 加上一份自然语言的使用手册， 就能把一个想法一路送到用户耳边——生成、合成、托管、订阅、收听，全链路没有一个环节需要自己开发 App。

起点 · 六七月想做一个 AI 播客 App

我很喜欢听播客，但 AI 播客一直没有像 AI 视频那样爆发。我想做一款 AI 播客 App：人人可以建立自己的专属知识库，通勤路上听一直想读的书，睡不着的时候放一段自己做好的播客。

碰壁投入产出比并不高

把它打磨成一个好用的产品，对我来说挑战很大，投入产出比也不高。豆包也有播客模型，但它有局限。 我开始怀疑：这条路是不是本来就太重了？

转机一个 GitHub 上的播客 Skill

看到"张咋啦"在 GitHub 上的播客 Skill，第一眼并没有被戳动。直到后来我想明白了一件事——

顿悟工作台已经成为基础设施

现在的设计哲学是：大多数人已经拥有一个"长得差不多"的工作台——Codex、Trae、Claude Code……它们正融入日常办公和生活。而 Apple Podcast 原生支持 URL 订阅，GitHub Pages 可以免费托管整条链路。用原生播客 App 收听，体验舒服到完全没必要再造一个 App。

现在把链路封装成一个好用的 Skill

所以，再去做播客 App 是浪费钱。要做的是把这个 Skill 打磨到小白可用：装进任何支持 Skill 的智能体——WorkBuddy、Trae、Codex、豆包都行。说几句自然语言，它就像一本使用手册，带你走完全程： 生成播客稿、TTS 合成音频、托管到 GitHub（或国内自托管平台）、拿到订阅 URL、在播客 App 里收听分享。
